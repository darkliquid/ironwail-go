# Package `compatrand`

## Purpose
The `compatrand` package provides a pseudo-random number generator (PRNG) that emulates the behavior of the standard C library's `rand()` function on Linux/glibc. This is necessary because Quake's gameplay logic (e.g., weapon spread, monster behavior) was originally written against the specific sequence of numbers generated by the glibc implementation. Using Go's `math/rand` would result in different gameplay outcomes, breaking "demo parity" and original feel.

## Key Types & Interfaces

- **`RNG`**: A struct that maintains the internal state of the random number generator. It includes a 31-degree state array and two pointers (`fptr` and `rptr`) to implement the additive feedback lag-generator algorithm used by glibc.
- **`shared`**: A package-global instance of `RNG` that mirrors the global nature of `rand()` in C.

## Core Workflow

1.  **Seeding**: The generator is initialized with a seed via `Seed(seed)`. If the seed is 0, it defaults to 1. Seeding populates the state array using a linear congruential generator and performs a "warmup" phase by generating several numbers to stabilize the state.
2.  **Generation**: Calling `Int31()` or `Int()` advances the internal state. The algorithm adds two elements of the state array together, updates one of them, and returns a 31-bit value.
3.  **Thread Safety**: The `RNG` struct uses a `sync.Mutex` to ensure that concurrent calls to the shared generator do not result in race conditions, which is important in the multi-threaded Go environment.

## Integration

- **Gameplay (Progs/QC)**: The QuakeC virtual machine often calls out to the engine's random function for game logic.
- **Client Effects**: Used for particle distributions, dynamic lighting flickers, and other visual effects that require deterministic randomness for demo playback.
- **World Generation/Physics**: Used anywhere the original engine relied on `rand()`.

## Learning Tips

- **Lagged Fibonacci Generator**: Research "Additive Lagged Fibonacci Generator" to understand the math behind the `state[r.fptr] += state[r.rptr]` logic.
- **Process Global State**: Note how the package exposes both a `New()` constructor for isolated instances and package-level functions for the shared instance. The engine almost exclusively uses the shared instance to match C behavior.
- **glibc Parity**: The constants `modulus = 2147483647`, `degree = 31`, and `sep = 3` are specific to the glibc implementation of `rand()`.
